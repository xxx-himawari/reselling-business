# Phase 4からの早期販売記録（移行契約案）

Phase 6完成まで販売を待たない。Phase 4では実市場・着地原価・悲観/標準利益・最大損失・最大仕入価格・推奨数量・人間の最終確認を満たし、少量仕入れを開始できる状態にする。

このフォルダーのCSVは空の記録テンプレート。Phase 1で購入承認・実績取込機能を実装したものではない。Phase 4の完了条件に以下の記録経路を含め、実商品を買う前に記録を始める。

- 各行にschema_version=1と一意なUUIDを付ける。Phase 1で作った商品・候補・提案・プランのUUIDを参照し、行番号やASINで結び付けない。
- 決定時の市場データ、出典/観測日時、費用、シナリオ、最終数量での再計算、最大損失の仮定、logic_versionをdecision_id.jsonに固定保存。最新情報で書き換えない。
- 金額は十進文字列、数量は整数、日時はISO8601のオフセット付き。空欄は不明、0は確認済み0。売価は単価、費用は総額。商品セット数はProductに合わせる。
- purchasesのUUIDは正式PurchaseLotへの移行時も維持。salesのpurchase_record_idを使って在庫と原価を配賦する。
- event_typeはSALE / RETURN / DISPOSAL / CORRECTION。返品・不良・処分・後日費用の明細を消さず、元取引をsource_referenceで参照する。顧客個人情報は記録しない。
- fee_statusはPROVISIONAL / FINAL。外貨は元金額と明示JPY換算値/根拠を両方記録。未確定実績を確定利益に混ぜない。
- Phase 6では原本をバックアップ→UUID/参照/数量/金額/チャネルを検証→dry run→transactionで取込→件数・数量・総額を照合。外部IDまたはrecord_idで再取込を重複排除する。
- 原本は運用データなのでこの公開リポジトリへコミットせず、ローカル/非公開のバックアップ先に保存する。正式なインポーターはPhase 6で実装する。
