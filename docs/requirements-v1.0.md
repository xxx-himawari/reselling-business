# 物販検証システム｜統合開発仕様書 v1.0

## 1. システムの目的

本システムの目的は、

**「売れそうな商品を探すこと」だけではない。**

商品候補の発見から、

**発見 → 仕入れ → 利益判定 → 行動 → 実績検証 → 学習**

までを一つにつなぎ、

> **経験を感覚ではなく、データとして蓄積する物販検証システム**

を作る。

短期目標は、

**2026年内 利益30,000円**

とする。

ただし30,000円はシステムに固定しない。

目標利益・期限・予算などは変更可能な設定値として持ち、将来、

- 月3万円
    
- 月10万円
    
- 月30万円
    
- 月100万円
    

などへ変更しても、システムを作り直さない構造にする。

# 6. 判定単位

最終的な比較単位は、

**商品 × 仕入先 × 仕入数量**

とする。

同じ商品でも、

仕入先A × 3個  
仕入先A × 10個  
仕入先B × 5個

では利益・必要資金・リスクが異なるため、別の

**Sourcing Plan**

として扱う。

**悲観 / 標準 / 楽観**

# 28. テスト数量

最初から大量仕入れしない。

需要・資金・最大損失・売切期間から、

**推奨テスト数量**

を出す。

例：

推奨：

3〜5個

理由：

10個では売切予測が長く、最大損失が設定値を超えるため。

# 63. システムの最終思想

このシステムは、

**「絶対に売れる商品を教えるツール」**

ではない。

目的は、

**仮説 → 少量仕入れ → 販売 → 検証 → 改善**

を高速化すること。

最初は一般市場データを使う。

↓

販売する。

↓

自分の実績が蓄積する。

↓

市場データと自分の実績を組み合わせる。

↓

自分が勝ちやすい商品条件が見えてくる。

↓

その領域の仕入条件を改善する。

↓

利益を拡大する。

最終的には、

> **「経験を感覚で積むのではなく、経験をデータとして積み、使うほど自分の判断精度が上がる物販システム」**

を目指す。
